Methods and assumptions

A transparent Salmon–DESeq2 pipeline with explicit eligibility rules and reference provenance.

Review outputsBack to overview

Analysis flow

  1. fastp
    Preprocesses reads and records JSON and HTML quality-control summaries.
  2. Salmon
    Quantifies transcript abundance against the selected transcriptome and gentrome index.
  3. tximport
    Maps transcripts to genes and writes gene-level counts and TPM matrices.
  4. DESeq2
    Models gene counts for condition-based differential analyses that meet the minimum requirements.

Snakemake connects these steps and preserves resumability. Harako freezes the normalized sample table, resolved configuration, analysis plan, tool versions, and reference provenance within each run before execution.

Counts are not TPM

Gene counts

tximport summarizes transcript estimates to gene-level counts. These counts are the input to DESeq2 because its statistical model expects count-scale information.

Gene-level TPM

TPM is retained as a gene-level abundance measure. It can help compare relative abundance within its appropriate context, but Harako never supplies TPM to DESeq2.

Interpretation

Neither file establishes biological independence, adequate power, or causal interpretation. Those judgments remain study-specific responsibilities.

Differential-expression eligibility

Policy version 1 allows inferential differential expression only when the normalized sample table contains at least two distinct conditions and every condition contains at least two valid samples. This two-sample threshold is a software gate, not a power calculation and not proof of biological replication.

Designs that meet the minimum analysis requirements use the configured condition-based contrasts. DESeq2 results, inferential plots, and optional enrichment are produced only when their prerequisites are satisfied.

QC-only means no inferential claims. A design with only one condition, or any design with fewer than two samples in a condition, keeps preprocessing, quantification, gene counts, TPM, technically possible descriptive normalization, applicable PCA and sample-distance QC, and reporting. It does not run contrasts, produce p-values or adjusted p-values, interpret volcano or MA plots, or run enrichment.

Reference provenance

Built-in presets are checksum-pinned Ensembl bundles. v0.2.0-beta.1 includes human GRCh38 / Ensembl 113, mouse GRCm39 / Ensembl 113, the backward-compatible mouse GRCm38 / Ensembl 102 preset, and rat mRatBN7.2 / Ensembl 113. Each bundle combines transcript FASTA, genome FASTA, and GTF assets whose SHA256 values are recorded in the repository manifest.

The frozen run records the selected preset, canonical identifier, release metadata, source URLs, and checksums. Custom reference files are supported, but the researcher must verify assembly and annotation compatibility.

Scientific limitations

  • The default condition-based design does not automatically model batch, pairing, repeated measures, or other covariates.
  • Small designs can yield unstable estimates even when they pass the minimum computational gate.
  • Harako cannot infer biological independence from filenames, labels, or replicate suffixes.
  • Degenerate count matrices can make DESeq2 median-ratio normalization impossible; the workflow fails explicitly in that case.
  • A valid checksum identifies reference content but does not prove that an assembly or annotation is biologically appropriate for a study.
  • The public beta is not clinically validated and does not replace expert statistical or biological review.
