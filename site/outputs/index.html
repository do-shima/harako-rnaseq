Preprocessing and quantification

fastp/

Processed reads plus per-sample JSON and HTML quality-control records. These artifacts document preprocessing rather than differential expression.

salmon/<sample>/quant.sf

Salmon transcript-level abundance, effective length, and estimated-count output for each sample. tximport consumes these files with the transcript-to-gene mapping.

Sample metadata

The normalized sample table links sample identifiers, conditions, and input files. SRA/ENA acquisition records preserve supported accession provenance.

Gene-level matrices

tximport/txi.tsv

The stable gene-level count matrix used as DESeq2 input. Counts, not TPM, feed the inferential model.

tximport/gene_tpm.tsv

Gene-level TPM when available. This is a descriptive abundance output and is never passed to DESeq2.

Mapping QC

tximport records mapping and identifier-normalization checks so transcript-to-gene compatibility problems can be diagnosed rather than silently ignored.

DESeq2 status and results

deseq2/status.json records the analysis mode, policy decision, condition counts, and actual artifact availability. Consumers should read this status rather than infer success or eligibility from file presence.

  • deseq2/results.tsv contains standard differential-expression columns in differential mode. In QC-only mode it has a header and zero data rows.
  • deseq2/normalized_counts.tsv contains descriptive DESeq2-normalized counts when normalization is technically possible.
  • PCA and sample-distance plots are produced when applicable. Inferential MA, volcano, adjusted-p-value, and fold-change plots are meaningful only in differential mode.
  • deseq2/qc_summary.tsv and deseq2/qc_summary.json summarize the mode and artifact availability.
QC-only mode never turns descriptive outputs into differential-expression evidence. Its results table remains empty of data rows, and inferential plots are marked not applicable.

Frozen run record

The run/ directory preserves immutable inputs for resuming and auditing a run. Key records include run/config_resolved.yaml, the normalized sample metadata, analysis plan, command and logs, reference provenance, Git revision, and run/versions.tsv. Later GUI edits do not rewrite these run inputs.

This separation is central to reproducibility: the run has a fixed identity and configuration, while Snakemake can safely determine which workflow steps need to resume.

Self-contained HTML report

The final report is always located at report/report.html relative to the run directory. It summarizes sample metadata, references, fastp, Salmon, gene counts and TPM availability, analysis mode, QC, and applicable differential results.

The report is static and self-contained: it does not require an internet connection, external JavaScript, fonts, analytics, or other web assets to render. Keep the surrounding run directory when the underlying result files and provenance also need to be audited.
