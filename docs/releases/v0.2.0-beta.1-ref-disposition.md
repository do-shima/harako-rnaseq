# v0.2.0-beta.1 ref disposition

This is a review plan, not an instruction to delete refs automatically.
Publication decisions must be recorded in the ignored maintainer-approval
record before the public-beta candidate gate can pass.

| Ref group | Current recommendation | Required decision |
| --- | --- | --- |
| `main` | Retain | None |
| Phase 5 audit branch | Delete only after its reviewed commits are in `main` | Confirm remote cleanup |
| Phase 5B release-blocker branch | Merge after CI; delete only after merge | Confirm remote cleanup |
| Merged public-beta documentation branch | Delete after verifying ancestry | Confirm remote cleanup |
| Obsolete development remotes | Inspect and delete only when fully contained | Confirm remote cleanup |
| Local branches with commits absent from `main` | Inspect unique commits; retain until resolved | Confirm local review |
| `v0.1.0` | Retain as historical release, or remove only by explicit decision | Record reviewed and approved retention decision |

Use these non-destructive commands during review:

```bash
git branch -vv
git branch --merged main
git log main..<branch>
git merge-base --is-ancestor <branch> main
git tag -n
git show v0.1.0
```

Manual deletion commands, if later approved, must be run separately by the
maintainer. This document deliberately does not prescribe force deletion.

The candidate gate requires explicit values for:

- `remote_branch_cleanup_reviewed`
- `local_unique_branch_reviewed`
- `v0.1.0_retention_reviewed`
- `v0.1.0_retention_approved`

Silence is not approval.
